# Contract: BankParser Plugin Interface (in-app, Kotlin)

**Scope**: Internal contract within the Android app. Adding a new bank = one new implementation of this interface + fixtures; the capture pipeline, outbox, and delivery code are never modified (FR-008, SC-005).

## Interface

```kotlin
interface BankParser {
    /** Display name, e.g. "MellatParser" — recorded on NormalizedTransaction.parserName */
    val name: String

    /** Bank slug, e.g. "mellat" — recorded on NormalizedTransaction.bank */
    val bank: String

    /** Package names (notifications) and/or SMS sender IDs this parser claims. */
    val supportedSources: Set<String>

    /** Cheap pre-check driven by RawEvent metadata (package/sender), not text parsing. */
    fun canParse(event: RawEvent): Boolean

    /**
     * Convert a raw event into a normalized transaction or a typed failure.
     * Must be a pure function of the event (no I/O, no clock access) — fixture-testable.
     */
    fun parse(event: RawEvent): ParseResult
}

sealed interface ParseResult {
    data class Success(val transaction: NormalizedTransaction) : ParseResult
    data class Failure(
        val reason: String,          // sanitized, non-sensitive detail for errorDetail
        val confidence: Confidence   // how sure the parser WOULD have parsed it
    ) : ParseResult
}

enum class Confidence { HIGH, MEDIUM, LOW }
```

## Rules

1. **Registration**: parsers are registered in `ParserRegistry` (ordered list). Registry selection: first parser where `canParse(event)` is true wins. If none matches, the event is retained and flagged `PARSE_ERROR` (never silently dropped — spec US6 scenario 2).
2. **Purity**: `parse()` performs no network/db/clock access. Timestamps come from the `RawEvent`; uuids are generated by the caller (pipeline), not the parser.
3. **Normalization**: all amount parsing MUST go through the shared Persian-number normalizer (research.md R10) — parsers must not hand-roll digit/separator handling (FR-010).
4. **Fingerprint**: computed by the pipeline after `parse()` succeeds, from the normalized fields (data-model.md §Fingerprint) — parsers never compute fingerprints themselves, guaranteeing cross-source consistency (notification vs SMS of the same bank produce the same fingerprint inputs).
5. **Safety**: parsers MUST NOT include raw message text in `Failure.reason`; sanitized summaries only (FR-023/028).
6. **Allow-list gate**: `canParse` is only consulted for events whose `sourcePackage` ∈ `ServerConfiguration.enabledBankPackages` (FR-001); the registry itself does not re-check the allow-list.
